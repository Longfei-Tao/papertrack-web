# 课题组论文投稿进度看板（PaperTrack Web）

一个**免费、响应式**的课题组论文投稿进度看板，支持**多课题组隔离 + 邀请码自助注册**：导师/同学各自登录，**只有本课题组成员才能看到本组进度**（组外的人看不到）；每个学生一个账号，**只能增删改自己名下的论文**，互不干扰；课题组管理员能看/改全部、生成邀请码、管理成员。

技术栈：**Cloudflare Pages（静态托管）+ Pages Functions（后端）+ D1（SQLite）**。全部在 Cloudflare 免费额度内，无需绑卡，适合学生低频使用。

---

## 一、核心特性

- **多课题组隔离**：一个数据库可承载无数个课题组（你以后可推广给其他导师团队），数据按 `team_id` 严格隔离，互不可见。
- **邀请码自助注册**：你「创建课题组」后自动得到一条邀请码，发给师姐/师妹/导师，他们**凭码自助加入**，不需要你一个个建账号。
- **成员可见**：未登录看不到任何数据；登录且是该组成员才能看/改本组进度。**非本组成员看不到。**
- **按归属权限**：member 只能改自己名下的论文；课题组 admin 可看/改全部。
- 顶部统计、进度/成员筛选、搜索、手机自适应（电脑表格 / 手机卡片）、**返修截止倒计时**（正确显示「距截止 N 天 / 已逾期 N 天」，不再出现 "-3 天"）。

### 角色说明（按课题组）

| 角色 | 能做什么 |
|------|----------|
| 访客（未登录） | 看不到任何数据，必须先注册/登录并加入某个课题组 |
| member（普通成员） | 看本组全部进度；增删改**自己名下**的论文；改自己密码 |
| admin（课题组管理员） | 看/改本组全部论文；生成/管理邀请码；移除成员；改自己密码 |

> 第一个创建课题组的人，自动成为该组 admin。之后可在「课题组管理」里把导师或其他人升为 admin（生成「管理员」角色邀请码，或未来支持直接改角色）。

### 字段说明

| 字段 | 含义 |
|------|------|
| 论文题目 | 论文标题 |
| 期刊名称 | 投稿期刊 |
| 影响因子 | 期刊 IF（数值，留空为未知） |
| 分区 | Q1 / Q2 / Q3 / Q4 / 待定 |
| 投稿进度 | 草稿 / 已投稿 / 审稿中 / 返修 / 接收 / 拒稿 / 已发表 |
| 负责人 | 自动填为当前登录账号的显示名（即"谁的文章"） |
| 投稿时间 | 投稿日期 |
| 返修截止 | 返修截止日期；到的话显示倒计时 / 逾期提示 |
| 备注 | 审稿意见、返修截止、校样等 |

## 二、本地预览（先看看效果）

需要本机有 Node.js（建议 18+）。

### 方式一：零依赖预览（推荐，最简单）

项目自带内存版预览服务，不需要安装 wrangler、不需要数据库：

```bash
cd papertrack-web
node start.cjs
```

会自动启动服务并打开浏览器访问 `http://localhost:4173`。**请一定用这个地址访问**，不要直接双击 `public/index.html`。Windows 用户也可以直接双击 `start.bat`。

> 内存版数据重启即清空，只适合本地看效果和试流程。

### 方式二：wrangler 本地模拟（接近线上环境）

```bash
npm install -g wrangler
cd papertrack-web
wrangler pages dev public
```

打开终端给出的地址（通常 http://localhost:8788）。首次需要本地建表：

```bash
wrangler d1 execute papertrack --local --file=./schema.sql
```

**首次怎么玩**：打开页面 → 右上角「注册 / 加入」→ 选「创建课题组」→ 填课题组名 + 你的账号 → 创建后你会得到一条**邀请码**。之后点「课题组管理」可复制邀请码、生成更多、看成员。点「载入示例数据」体验界面。

> 本地 D1 数据存在本机，不会上传；纯属预览。要真正分享给别人必须走下面的部署。

### 本地初始化数据库（首次）

```bash
wrangler d1 execute papertrack --local --file=./schema.sql
# 若提示数据库不存在，先：wrangler d1 create papertrack --local
```

## 三、部署上线（分享给导师/同学）

### 1. 登录 Cloudflare

```bash
wrangler login
```

浏览器弹窗授权（没有 Cloudflare 账号就免费注册一个）。

### 2. 创建 D1 数据库

```bash
wrangler d1 create papertrack
```

命令返回 `database_id`（形如 `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`）。把它复制到 `wrangler.toml` 里替换 `REPLACE_WITH_YOUR_D1_ID`。

### 3. 建表

```bash
wrangler d1 execute papertrack --file=./schema.sql
```

### 4. 部署前端 + 后端

```bash
wrangler pages deploy public
```

首次会让你输入一个项目名（如 `papertrack`），之后给一个 `*.pages.dev` 的公网地址。

---

## 四、首次配置（重要）

1. 打开 `*.pages.dev` 地址，点右上角「📝 注册 / 加入」→ 选「创建课题组」→ 填组名 + 你的账号密码。你即为该组 **admin**，并自动获得一条邀请码（提示里会显示，也可在「课题组管理」复制）。
2. 把 **网站地址 + 邀请码** 发给导师、2 个师姐、1 个师妹。
3. 他们打开地址 → 「注册 / 加入」→ 选「凭邀请码加入」→ 填信息 → 自动进组。
4. （可选）若想让导师也当管理员：在「课题组管理」生成一个「管理员」角色的邀请码发给他，或之后加直接改角色的功能。
5. 改自己密码：用户菜单 → 修改密码。

> **没有任何默认密码 / 全局管理员**。每个课题组都是创建者自己当 admin，互不影响——这就是"可推广给其他团队"的关键。

## 五、日常使用

- **你（admin）**：登录后看/改全部；「课题组管理」里生成邀请码、看成员、移除成员；「只看我的」快速过滤；顶部可切换你加入的多个课题组。
- **师姐/师妹/导师（member）**：用自己账号登录 → 只能添加/编辑/删除**自己**的论文，互不干扰；也能切到别的组（若加入了多个）。
- **改数据后**：点「刷新」即可看到最新内容（数据在云端 D1，全组实时一致）。

## 六、成本

Cloudflare 免费额度（学生完全够用）：

- Pages 静态托管 + Functions：每日 10 万次请求免费
- D1 数据库：每天 500 万次读、10 万次写免费，存储 5 GB 免费
- 一个课题组几十篇论文、几个人看，几乎不可能触顶；多团队也共用同一额度。

## 七、目录结构

```
papertrack-web/
├── wrangler.toml                       # 部署配置（D1 绑定）
├── schema.sql                          # 建表：users / sessions / teams / team_members / invite_codes / papers
├── functions/
│   ├── _lib/
│   │   └── auth.js                     # 共享鉴权（密码哈希/会话/团队归属校验）
│   └── api/
│       ├── register.js                 # 自助注册：创建课题组 / 凭邀请码加入
│       ├── login.js                    # 登录（返回 token + 团队列表）
│       ├── logout.js                   # 退出
│       ├── me.js                       # 当前用户 + 团队 / 改密码
│       ├── teams.js                    # 我加入的团队列表
│       ├── teams/[id]/invites.js       # 邀请码：列出 / 生成（仅 admin）
│       ├── teams/[id]/members.js       # 成员：列出 / 移除（仅 admin）
│       └── papers.js                   # 论文：按 team_id 隔离，成员可见，归属校验
└── public/
    ├── index.html                      # 页面结构（注册/登录/课题组管理/改密弹窗）
    ├── styles.css                      # 响应式样式
    └── app.js                          # 前端逻辑（团队切换、注册、权限、倒计时）
```

## 八、常见问题

- **打开页面一片空白 / 提示"请先登录"**：现在要求登录且是成员才能看。先用「注册 / 加入」创建或加入课题组。
- **提示"数据库未绑定"**：部署时 D1 没建或 `wrangler.toml` 的 `database_id` 没替换。重做第三、四步。
- **师姐误改了别人的论文？**：不会——member 只能改自己 `owner_id` 的论文，后端（`papers.js`）强制校验；admin 才能改全部。
- **想把导师也设为管理员？**：在「课题组管理」生成一个「管理员」角色邀请码发给他，让他用该码加入即可成为 admin。
- **推广给其他团队**：别的导师自己打开地址 → 「创建课题组」→ 他变成他组的 admin、生成他自己的邀请码。你什么都不用做，平台只是多存了一个 team，所有组共用同一套代码和同一个免费数据库，互不可见。
- **想加字段（如 DOI、基金号）**：在 `schema.sql` 给 `papers` 加列 + 改 `functions/api/papers.js` 的读写 + 改 `public/index.html` 表单与 `public/app.js` 渲染即可。
- **忘了密码**：没有密码找回（刻意简单）。admin 可在「课题组管理」移除该成员，让其用新邀请码重新加入；或 `wrangler d1 execute` 直接改库。
